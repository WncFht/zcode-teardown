# Lane C9 — protocol surface (ACP / IPC / endpoints / proxy)

Scope: the wire-facing surface of all 56 extracted versions (2.2.0→3.14.0). Sources: `signatures/<ver>.json` (acp_methods / ipc_channels / endpoints), `diffs/*.md`, `extracted/<ver>/`, plus an RPC registry table extracted from each `glm/zcode.cjs` and per-version method matrices. Caveat on signatures: `acp_methods` mixes three extractors — quoted `"ns/method"` strings, `method:'x'` literals, and `acp.*` telemetry events — so it covers at least four distinct protocols and picks up non-method literals; each attribution below was re-verified by grep.

## ACP surface

### Two protocol eras

- **2.x (2.2.0–2.13.0): Zed ACP (Agent Client Protocol), JSON-RPC over stdio.** The Electron host is the ACP _client_; per-provider agents are spawned with `stdio:["pipe","pipe","pipe"]` (`extracted/2.13.0/app/out/host/index.js:28911`). Method surface = the upstream ACP schema vendored in `extracted/2.13.0/acp/node_modules/@agentclientprotocol/sdk/dist/schema/index.js` (`PROTOCOL_VERSION = 1`, line 41): `session/new`, `session/load`, `session/prompt`, `session/cancel`, `session/update`, `session/request_permission`, `session/set_mode`, `session/set_model`, `session/set_config_option`, `fs/read_text_file`, `fs/write_text_file`, `terminal/*` (create/output/kill/release/wait_for_exit). Providers: `claude` (`acp/` = `@agentclientprotocol/claude-agent-acp`), `codex` (`codex/` = `zcode-codex-bundle 1.0.0` wrapping `@zed-industries/codex-acp` + native `codex-acp-linux-x64`), `gemini` (`gemini/gemini.js` implements the same surface natively), `opencode` (binary), `glm` (`glm/zcode-acp`, a 168 MB ELF `zcode-cli` — the direct ancestor of 3.x `glm/zcode.cjs`).
- **3.x (3.1.0+): ZCode's own JSON-RPC 2.0 registry** inside `glm/zcode.cjs` — the canonical method map is the `dr` object at char ~489029 in `3.12.3/glm/zcode.cjs`. Transport: host spawns `zcode.cjs app-server --stdio` under `ELECTRON_RUN_AS_NODE=1` (`extracted/3.12.3/app/out/host/chunk-OIOBEZTZ.js` char ~156260, with monorepo fallback `apps/zcode-cli/packages/cli/dist/zcode.cjs`; overridable via `ZCODE_AGENT_SERVER_COMMAND`). The boundary diff records it as `engine: gemini+acp+acp-proxy -> glm-zcode` (`diffs/2.13.0__3.1.0.md`). Every 2.x method name is gone at 3.1.0 except ones that coincidentally share names (`session/list`, `session/resume`, `session/fork`, `session/close` appear in both lines — but in 2.x they come from the vendored ACP sdk schema, in 3.x from `dr`).

### Auth flow

- **3.x**: dual providers — bigmodel (`authorizeUrl=bigmodel.cn/login`, appId `zcode`) and zai (`chat.z.ai/api/oauth/authorize`, appId `client_P8X5CMWmlaRO9gyO-KSqtg`, biz login `api.z.ai/api/auth/z/login`). Both redirect to `zcode://oauth/callback` (`setAsDefaultProtocolClient("zcode")`, `main/index.js` char ~356211) → renderer via `zcode:oauth-callback`. Code exchange POSTs `{provider,code,redirect_uri,state}` to **`zcode.z.ai/api/v1/oauth/token` (server-side broker)** → `{access_token, zcodeJwtToken}`; zai token is further exchanged at `/api/auth/z/login`. ## acp-proxy

`acp-proxy-runtime/` ships in **every 2.x** tree (2.2.0–2.13.0, `dist/` ~22 files), spawned by the Electron **host** as `spawn(process.execPath, […/acp-proxy-runtime/dist/cli.js], {ELECTRON_RUN_AS_NODE:"1", ZCODE_ACP_PROXY_DATA_DIR})` (`2.13.0/app/out/host/index.js:25041`, path resolved at :24895). It listens `127.0.0.1:0`, prints a `{"type":"ready",proxyUrl,port,caCertPath,captureFilePath}` ready line (`dist/cli.js:50-56`), and takes JSONL route-control on stdin (set/delete/pin/unpin_route, `dist/runtimeRoutes.js:19-39`).

**It sits between the bundled agent CLIs and their model providers.** Agents (`SUPPORTED_PROXY_PROVIDERS` = claude/codex/opencode/gemini/glm, `host/index.js:24870-24878`) get `HTTP_PROXY/HTTPS_PROXY` + CA env (`NODE_EXTRA_CA_CERTS`/`CODEX_CA_CERTIFICATE`/`SSL_CERT_FILE`) via `buildAcpProxyEnvPatch` (:24840-24868). CONNECT tunnels are byte-sniffed (0x16=TLS → MITM, else plain tunnel, `dist/proxyServer.js:160-180`); MITM uses a self-generated root "ZCode ACP HTTPS Proxy Root CA" minting per-host 30-day leaves (`dist/certificate.js`). Also deployed to SSH remotes at `~/.zcode/server/acp-proxy-runtime` (`app/out/main/chunk-YGMUHZ3H.js:2638-2685`).

Three roles:

1. **Dialect translation** — marker headers in workspace codex `config.toml` `http_headers` select compat shims: `x-zcode-openai-wire-compat` → `/responses`→`/chat/completions`; `x-zcode-codex-wire-compat: gemini-generate-content` → `/v1beta/models/{m}:(stream)generateContent`; `…: anthropic-messages` → `/v1/messages`; `x-zcode-gemini-wire-compat` → Gemini→OpenAI; `x-zcode-codex-model-override` + `httpForwarding*ModelOverride.js` rewrite `model` fields (`httpForwarding*.js`, `*Compat.js`; trigger check `host/index.js:8856`).
2. **Per-workspace hot-swappable routing** — routes keyed `claude:<sha256(workspaceKey)[:16]>` carry `targetBaseUrl` + auth headers + `model` built from workspace claude settings `env.ANTHROPIC_BASE_URL`/`ANTHROPIC_AUTH_TOKEN` (:29214-29275); selected via `x-zcode-proxy-route-key`, session-pinned via `x-claude-code-session-id` (`runtimeRoutes.js:67-92`).
3. **Opt-in traffic capture** — "ACP 代理流量" viewer: NDJSON events → `AcpProxyTrafficStore` → `zcode:acp-proxy-traffic-*` IPC + dedicated window (`app/out/main/index.js:5399,9717-9720`); bodies+CA under `getAppConfigDir()/acp-traffic-proxy`, 3-day retention (`host/index.js:551`, `dist/capture.js`).

**3.x successor: none** — dir, spawn code, routes, and IPC all vanish at 3.1.0. `glm/zcode.cjs` speaks `/chat/completions`, `/responses`, `/messages`, `generateContent` dialects natively in-process (per-provider `config.url({path})` dispatch), so the external translation proxy became obsolete; a user-supplied `acpProxyUrl`/`proxyUrl` env patch survives for user proxies (`3.12.3/app/out/host/index.js` char ~270 region).

## Protocol versioning / handshake

- **2.x**: ACP `initialize` handshake, `PROTOCOL_VERSION = 1` (`acp/node_modules/@agentclientprotocol/sdk/dist/schema/index.js:41`). No further negotiation.
- **3.x**: layered negotiation —
    1. `server/discover` (appears **3.7.3**) with MCP-style `_meta` keys `io.modelcontextprotocol/{protocolVersion,clientInfo,serverInfo,clientCapabilities}` (`3.12.3/glm/zcode.cjs` char ~6323438); response carries `supportedVersions` — the supported list `["2025-11-25","2025-06-18","2025-03-26","2024-11-05","2024-10-07"]` is the MCP spec-version set — and picks `supportedVersions ∩ clientModernVersions`, else `kind:"legacy"` (char ~6320449). Also `runtime/capabilities` (registry entry by 3.12.x) and `ping`/`notifications/initialized` MCP boilerplate.
    2. **Dated wire eras**: `protocolVersion ∈ {legacy, auto, "2026-07-28"}` (string first appears 3.7.3, count 6→7 by 3.12.3). The `2026-07-28` era adds strict `_meta`-envelope validation, era-mismatch drops (`Era mismatch on inbound notification … classified as X but this instance serves Y`), and restricts some result types to `complete`; `_negotiatedProtocolVersion`/`_negotiatedWireCodec` track the session state (char ~6125514+).
    3. **Remote workspaces**: `GET /api/server-info` → `{serverId,version,protocolVersion:1,authRequired,workspaces[],capabilities:{desktopContinuous,websocketRpc}}` (schema `Qto`, char ~599556) + `GET /api/rpc-host-capability`, then WS `wss://zcode.z.ai/ws/host` with `x-zcode-rpc-{client-mode,host-capability}` headers (char ~621328) and `?token=` auth.
    4. **Event-stream envelope** separately versioned `protocolVersion:1` `{sessionId,logEpoch,seq,revision,control,availability,inputRouting}` (char ~401289); `session/subscribe` `deliveryKind ∈ {desktop-continuous, web-remote-replayable}` — the earlier third kind `bot-channel-continuous` (documented in `refs/zcode-reverse-engineer`) no longer exists in 3.12.3.
    5. `startup/storage{Path,Prepared,State,PathReady}` discriminated-union handshake added 3.12.2 (storage-path negotiation before the RPC registry comes up).
- Cross-check: `refs/zcode-reverse-engineer/ANALYSIS_REPORT.md` (3.0.1/2.13.0 study) matches our corpus on OAuth→JWT, stdio RPC, and proxy-compat; diverges only on the dropped `bot-channel-continuous`.

## REVIEW

- **Signature `acp_methods` ≠ wire method list.** It merges ≥4 protocols (agent RPC registry, CUA broker, browser-use MCP tools, MCP-schema literals) plus non-method literals (`acp.exe`, `MERGED`, `before/after`, CSS values). The authoritative 3.x method list is the `dr` registry extracted from each `glm/zcode.cjs`; the 2.x list is the vendored ACP schema. Any per-method claim should cite the registry/schema, not raw signature presence.
- **`v4/*` family undercounted by signatures** (only `v4/conversation/frame` matched the `method:` regex); the real family is ~17 methods — verified in zcode.cjs but its server-side role (remote relay vs in-app stream) is inferred from `clientMode`/`logEpoch` fields and host consumption, not from a spec doc.
- **`zcode:` IPC enum↔handler** mapping verified for major clusters; the ~95 handler sites are all in one file but were sampled, not exhaustively line-indexed.
- **2.x endpoint count is agent-vendor noise** — signature endpoints for 2.x (~2.3–2.7k after unified-extractor regen) include gemini-cli/codex/opencode/claude bundled code; app-owned endpoints were re-derived by grepping `app/out` only (~125 at 2.13.0). A clean per-source split was not recomputed for every 2.x version.
- **Unverified**: whether `server/discover`'s `supportedVersions` are MCP-spec versions or ZCode's own (they match MCP dates — likely intentional MCP alignment); what exactly `v4/telemetry/event` reports; whether the 3.12.x `provider/*` methods fully subsume the removed `workspace/*` registry ops (names suggest yes: `providerUpdateAccountConfig`, `providerTestModelConnectivity`).
- **Security-relevant findings for other lanes**: 2.x ships `BIGMODEL_LEGACY_APP_SECRET_FALLBACK` (an OAuth client secret) in plaintext `app/out/host/index.js:44137` — removed from the client in 3.x (moved to server-side broker); the acp-proxy installs a **self-signed root CA** (`ZCode ACP HTTPS Proxy Root CA`) into bundled agents' trust stores for MITM — present all of 2.x, gone 3.x; intranet IPs + staging hosts ship in release binaries; Telegram/Feishu bot integrations can drive tasks remotely (`bots:task*`, `zc:*` callback encoding).
