## 关键技术发现（过程层）

### CDN rolling-pull 与替代阶梯

linux-x64 artifact 不是稳定下架而是**成波 404 且会回摆**，探测窗口以秒—分钟计。应对：probe→命中即 chunked 下载（24MiB，flaky 时 8MiB ×8 重试），不可"先记 URL 后批量拉"。替代阶梯 `linux-arm64.AppImage > win-x64.exe > mac-arm64.zip > mac-arm64.dmg > mac-x64`——AppImage 的 `resources/` 与 deb 完全同构（host ELF 逐字节相同，`7f7881d0`），win/mac 只保 JS/asar/config 载荷。

### `cdn.zcode-ai.com` 是 fixture 死域

旧域 DNS 解析到 198.18.4.156（198.18/15 benchmark 保留段）：能回 206 但下载必然中段死。唯一真实 CDN 是 `cdn-zcode.z.ai`。教训：**206 不等于活着**，校验必须落在 Content-Range + 分段完整性上。

### 签名 stub 事故

extractor 对空 extracted 目录会产出"结构完整但全空"的 1KB JSON stub——schema 过、内容假。审计方法：文件大小 + 类别计数非零。3.2.0/3.2.1 曾中招，重抽修复；全量扫后无其它受害者。教训：**cheap verification 也要看内容量，不只是结构**。

### 提交拓扑 ≠ 版本拓扑

并行 lane 的 commit 顺序依赖完成先后，`git log A..B` 会跨 lane 误报边界；一律 `git diff vA..vB`。同理 diff 配对必须按 manifest 发布序而非目录序，否则跨缺口配对出假边界。

### 引擎侧版本表是隐藏证据源

win 树 tools/ 无 bfs.exe 一度无法区分"版本差异"与"平台差异"；`glm/zcode.cjs` 内嵌 `fCa` 表（`bfs:{linux:"v4.1.1-2"}, ripgrep:{darwin:"v13.0.0-10",linux:"v14.1.1-1"}, ugrep:{linux:"v7.5.0-2"}`）逐平台登记发行 tag，3.6.1-win 与 3.6.5-deb 逐字相同——直接把工具组上线边界收窄到最窄 3.5.3→3.6.1，同时证明 bfs 是 linux-only、darwin rg 停在 13。**bundle-meta.json 与引擎版本表互为冗余证据，缺 binaries 的平台也能定版。**

### Electron 宿主零变更

47 个 linux-x64 宿主样本 sha256 全同（`7f7881d0`，206036184 B，Electron 41.0.3/Chromium 146/Node 24.14.0）；2 个 linux-arm64 样本互同（`abfeaa0e`）。全部产品演化都在 resources/ 内。win PE 与 mac Mach-O 宿主因格式固有差异不做跨版 sha 比对。

### sshcrypto.node 是异构 dead payload

所有 linux-x64 树中的 `ssh2/…/sshcrypto.node` 均为 **ARM aarch64** ELF（2.2.0–3.12.3 `file` 实测全同）——x64 宿主永远无法加载，ssh2 只能走纯 JS crypto 回退（win 树干脆不编该绑定，殊途同归）。3.6.5→3.7.3 观测到的"重编"（build-id `92881f85`→`2834a3cb`）重编的是错误架构的二进制。pty/koffi/sharp 均正确 x86-64。教训：**.node 的存在不等于可用，`file` 架构核对应属签名抽取的常规步骤**。

### 签名抽取器多代混跑事故

签名在 15:50–16:34（peer 批次）与 20:08–20:10（补抽 4 版）两个窗口生成，期间抽取器被反复修改、20:38 才提交终版——committed corpus 实为**多代混合**。验证方法：用终版抽取器在同一棵树重抽比对——3.12.2 端点 358→283，丢失 75 项全部为 vendored 文档/规范 URL（chevrotain.io、wikipedia、whatwg、ietf、unicode.org、stackoverflow、example.com）与 `plan:lesson_plan` 伪条目，gained=0，证明终版仅更严格不丢真信号。处置：**全量 55 版重抽 + 52 份 diff 重生成**，语料回到单代一致；3.12.2→3.12.3 归零，与 c6"真实 delta 只有 updater fix"吻合。教训与 stub 事故同源：**可再生产物的中间代不能混入最终语料，定版即全量重跑**。

### `app-update.yml` localhost:8081 真相

c3 在 3.3.6 标记"dev feed 泄漏进 release"、epoch-gap 怀疑"QA 构建混入 CDN 语料"——全语料核查：≤3.3.5 全部 21 版 yml 为 `cdn.zcode-ai.com` 真 feed，≥3.3.6 全部 25 版统一为 `http://localhost:8081`。这不是事故而是**随 3.3.6 自托管更新管线（`/api/v1/releases/electron/manifest` + 更新 UI IPC 面）落地时的刻意 stub 化**：electron-updater generic feed 被置空，真实 feed 改由应用内计算（domestic/overseas CDN + `ZCODE_UPDATE_FEED_URL` 覆盖）。单版可疑样本在全语料尺度上是边界证据。

## 流程/舰队纪律复盘

有效的：

- **lane status.jsonl**（ver/stage/ok/counts/error）让恢复作业可断点续审；cheap-verification-first（sha512/counts/JSON）挡下了 stub 事故外的全部假阳性。
- **leader 独占 git-history**：全任务零冲突；`commit.lock` flock 兜底并行 commit。
- **agent 交付物落盘即关**：roster 无僵尸，产出以仓库为准。
- **REVIEW 节**：c5 跨缺口临时结论显式标注 provisional，避免把"3.7.3 AppImage 推断"写成"deb 事实"。
- **替代树 SOURCE.json**：diff header 自动挂 WARNING，读者不会被 apparmor/.node 格式噪音误导。

出了问题的：

- API 中断致全 fleet 死亡一次——恢复后改为少而精的 C-lane 重开。
- `set -u` + 空关联数组、`$PKG` 相对路径、7z `resources` 无通配三处脚本 bug 各烧了一轮恢复窗口；均已修。
- `sources.json` 构建器曾把 3.7.1 的 exe URL 泄漏进 3.7.2 条目——**stale-URL 复用是 probe-fail 分支的坑**，已对每版重探修正。
- markdownlint/prettier 链对 notes 的改写—readd 循环两次拦下提交；属预期行为但首次遇到时费解。
- lane 报告的若干断言需逐一回源核实：c8 声称"3.12.3 有 acp/ 回归"经 `git ls-tree -r` 证伪（3.x 全线无），"config/ 3.7.5 起"实为 3.5.2；c6 的"yml 切换 3.4.0"实为 3.3.5→3.3.6。**lane 结论照收前必须用 repo tag/全语料扫描复核**——本次共修正四处。
